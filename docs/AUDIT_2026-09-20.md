# Repository audit — 2026-09-20

Scope: GitHub `main`, production Supabase schema/functions, beta cockpit state, Summary finalization, and AI-learning source parity.

## PASS

- Stable `/` does not load cockpit UI; compact cockpit remains isolated at `/beta.html`.
- Case Assistant async responses are case-bound: responses are cached by case ID and stale requests are not painted onto another selected case.
- Generate Summary persists the case before invoking server-side generation.
- Finalize Summary uses the authenticated `clinical-store/finalize_patient` path and creates an immutable revision through `finalize_case_atomic`.

- Delete Case is routed through the server-side clinical-store action.
- Production Case Assistant state is persisted server-side and browser roles do not need direct table access.

## BUG / DATA-CONSISTENCY RISK

### Arrival metadata coverage is inconsistent in finalized learning snapshots

`cases.arrival_mode` and `cases.arrival_other` exist and production `generate-summary` reads them. However the current `clinical-store` source does not include arrival metadata in:

- `saveState()` / `savePatient()` case upserts;
- `finalizePatient()`'s atomic case payload;
- `corpusSnapshot()`.

The production `finalize_case_atomic` definition also does not insert/update the arrival columns. Fresh production inspection found 15 finalized revisions with embeddings, but only 2/15 `case_snapshot` rows currently contain `arrival_to_sbo`. The current clinical-store source does not add that field, so arrival-style learning/retrieval coverage is inconsistent even though Generate Summary can use arrival from the live case row.

This should be fixed as a dedicated migration + clinical-store change, not hidden inside repo cleanup.

### Browser UPDATE access still bypasses the privacy-write invariant

Production currently grants `authenticated` both `SELECT` and `UPDATE` on `public.cases`, and the frontend runtime patch directly updates case metadata/free text. This is inconsistent with the intended invariant:

```text
Browser -> clinical-store -> de-identification -> PostgreSQL
```

Move the remaining direct updates behind `clinical-store`, then revoke browser UPDATE when the UI no longer depends on it.
